# Updating SupportLab

Keep the GitHub repository private. Repository access and website access are separate; do not enable public GitHub Pages for this private website.

## Local work

Use Node.js 24. Run `npm ci` once in a clean checkout, then `npm run preview:local` for the website. The local preview is http://127.0.0.1:4173. No API key is needed.

Edit the root website files, including `app.js`, `data.js`, `style.css` and `ai.js`. The `public` copies and `lib/workspace-shell.ts` are synchronized during `npm run build`. The browser AI runtime in `vendor/webllm.js` is generated by the pinned dependency; edit its source integration rather than the bundle.

## Review an update

1. Create a short-lived branch for the change.
2. Run `npm test` and `npm run build`.
3. Check the affected page in a real browser. For AI changes, verify actual model loading and a synthetic response on a WebGPU-capable device; mocked tests do not establish model quality.
4. Open a pull request, review the changes and merge after the checks pass.

The GitHub Actions workflow runs the tests and production build for pull requests and updates to `main`. It performs checks only. Website deployment will be connected to an authenticated host after browser acceptance checks and hosting access are available.

Never commit `.env*`, API keys, downloaded model weights, dependency folders or local runtime caches. The AI runs on the learner's device and needs no hosted inference credential.

## Recover an earlier version

Use GitHub's change history to identify the last working commit. Revert the problematic change through a new reviewed commit so the history remains understandable. Progress is stored in each learner's browser; preserve the storage format or include a migration when changing it.
